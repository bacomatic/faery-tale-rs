# T1.3 — Item/quest data fold-in

> Read [`_SHARED.md`](_SHARED.md) first. Implementer produces the assets; a separate Reviewer accepts them by inspection (human-in-the-loop).

## Dependencies
T0.1.

## Inputs (read-only)
- `tools/extract_item_effects.py`, `tools/extract_quest_data.py` (existing)

## Implementation
1. Run both existing extractors.
2. Normalize their output into `assets/tables/` (consistent JSON style, stable key order).
3. Ensure file names don't collide with T1.2 outputs.

## Outputs
- Item-effects and quest-data JSON under `assets/tables/`.
- Add T1.3 items to `assets/tables/verify.json` (spot values + source citations) so a reviewer can eyeball them in the review app.

## Implementer self-check
- Valid JSON; no schema/name collisions with T1.2.

## Manual verification (human-in-the-loop)
Work through T1.3's page in the review app (items from `assets/tables/verify.json`); inspect the JSON against source:
1. `json.load` every produced file — must parse.
2. Confirm zero filename collisions with the T1.2 table set.
3. Spot-check a handful of item/quest entries against the original source the extractors read.
Report ACCEPT/REJECT.

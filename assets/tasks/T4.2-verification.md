# T4.2 — Bundle acceptance (human-in-the-loop)

> Read [`_SHARED.md`](_SHARED.md) first. This is the **final, one-time human acceptance** of the
> committed `assets/` bundle. There is no regeneration harness and no determinism check — we accept
> the assets that exist, by inspection.

## Dependencies
T4.1 (manifest) and every extractor task accepted.

## Inputs (read-only)
- The committed `assets/` tree, `assets/manifest.json`, and every `verify.json`
- The review app (`tools/review/`) and `assets/tasks/review_results.json`

## Implementation
There is **no top-level `assets/VERIFY.md`**; the review app's task list shows every task's state
(latest verdict, stale ACCEPTs, validation errors). Add T4.2 items to the root `assets/verify.json`:
a short bundle-wide walkthrough sampling one of each kind (a tile atlas, a sprite sheet, a screen,
a world preview, an SFX WAV, a music preview, a table/text JSON), each pointing back at its
per-task `look_for`, plus a bundle-wide item: all planned resource types present per the plan's
Output layout. No code is required.

## Outputs
- `assets/verify.json` (T4.2 items)

## Implementer self-check (optional aid)
- The app shows no validation errors; every other task's latest round is ACCEPT and none is stale;
  the bundle contains no leftover `.gitkeep` or debug/scratch files.

## Manual verification (human, by perception)
In the review app — the final walkthrough of a bundle whose parts you already accepted per-task:
1. Task list: every task shows ACCEPT, none stale, no validation errors.
2. Work through T4.2's page: each sampled asset still matches its description; SFX and music
   preview match their cues.
Report ACCEPT/REJECT with the specific assets inspected.

# T2.5 — World data extension

> Read [`_SHARED.md`](_SHARED.md) first. Implementer produces the assets; a separate Reviewer accepts them by inspection (human-in-the-loop).

## Dependencies
T0.1 (plus T2.2's atlases if the previews composite real tiles — color-coded renders need no dep).

## Inputs (read-only)
- `tools/decode_map_data.py` (existing, ~1,467 lines of map/sector/terra logic)
- ADF `src/assets/image` (sector/map/terra blocks)

## Implementation
Extend `tools/decode_map_data.py` to emit per-region JSON:
1. Sector tile-index grid.
2. Region map.
3. Terra/collision flags: **high nibble = feature type, low nibble = mask-application mode.**
4. **Preview renders** under `assets/world/previews/`: per-region map PNGs (tiles composited
   from the T2.2 atlases, or color-coded terra/collision overlays) so the reviewer can recognize
   the world by sight. Non-authoritative; ship with the bundle.

## Outputs
- `assets/world/*.json` (per region) + `assets/world/previews/*.png`
- `assets/world/verify.json` (T2.5 items) — expected region count/grid dims as `counts` + preview file ↔ "what you should see"
- `tools/tests/test_decode_map_data.py` (optional aid, not a deliverable)

## Implementer self-check (optional aid)
- Terra decode matches hand-decoded nibbles on spot regions; grid dims and region count match
  the `file_index`/memory notes.

## Manual verification (human, by perception)
Work through T2.5's page in the review app (items from `assets/world/verify.json`); **look at the previews**:
1. Open each region's preview render: it's the world you know — Tambry where Tambry belongs,
   coastlines/rivers/roads in the right places, dungeons laid out correctly.
2. Glance at a terra/collision overlay preview: blocked areas sit where the game blocks you
   (water, walls, mountains).
3. Sanity: the app's actual-vs-expected region count and grid dimensions agree.
Report ACCEPT/REJECT with the regions viewed.

# T1.2 — Gameplay tables extractor

> Read [`_SHARED.md`](_SHARED.md) first. Implementer produces the assets; a separate Reviewer accepts them by inspection (human-in-the-loop).

## Dependencies
T0.2 (C-array extractor).

## Inputs (read-only)
- `src/fmain.c`, `src/fmain2.c`, `src/ftale.h`
- `reference/RESEARCH-data-structures.md` (field names/semantics)

## Implementation
Export each table to `assets/tables/*.json` via `extract_table.py`, with field names from the
reference doc:
`statelist`(87×4), `encounter_chart`(11×6), `inv_list`(36), `weapon_probs`(32),
`treasure_probs`(40), `rand_treasure`(16), `diroffs`(16), `fallstates`(24),
`setfig_table`(14×3), `file_index`(10×9), `trans_list`(9×4).

## Outputs
- `assets/tables/{statelist,encounter_chart,inv_list,weapon_probs,treasure_probs,rand_treasure,diroffs,fallstates,setfig_table,file_index,trans_list}.json`
- `assets/tables/verify.json` (T1.2 items, `view: table`) — expected dimensions per table as `counts` + spot values with source `citations` (file:line)
- `tools/tests/test_extract_tables.py` (optional aid, not a deliverable)

## Implementer self-check
- Each table's shape/count matches the spec above; spot-check values vs source.

## Manual verification (human-in-the-loop)
Work through T1.2's page in the review app (items from `assets/tables/verify.json`); inspect the JSON against source:
1. For **3 different** tables (pick `statelist`, `file_index`, `setfig_table`), hand-locate the
   C array and transcribe the first row and last row; compare vs JSON.
2. Confirm every file's element count exactly matches the spec dimensions above.
3. Confirm `file_index` block numbers agree with the `file_index[]` C array in `src/` /
   memory note (TERRA_BLOCK=149, image groups of 40 blocks).
Report ACCEPT/REJECT with transcribed rows and the count table.

# T4.1 — Bundle index (manifest)

> Read [`_SHARED.md`](_SHARED.md) first. Implementer produces the manifest; a separate Reviewer
> accepts it. The manifest is **data that ships with the bundle**, describing the committed assets
> — not a driver that regenerates them.

## Dependencies
All extractor tasks (Wave 1 + Wave 2) — the assets must already exist and be accepted.

## Inputs (read-only)
- The committed `assets/` tree

## Implementation
Author `assets/manifest.json` — an index of the **committed** bundle. Per shipped file:
path, type, byte size, **SHA-256**, and a source reference (where it came from in `src/`/`src/assets`).
Every `verify.json` is a shipped file and is listed like any other (source reference: the task
that authored its items).
A small throwaway helper under `tools/` may generate it by walking `assets/`, but the manifest
itself is the deliverable; the helper is a provenance byproduct. Do **not** build an orchestration
driver that re-runs the extractors.

Add T4.1 items to the root `assets/verify.json`: `manifest.json` (`view: json`) with a `count`
of entries and a `look_for` of what it should cover.

## Outputs
- `assets/manifest.json` (ships with the bundle)
- `assets/verify.json` (T4.1 items)

## Implementer self-check (optional aid)
- Manifest covers every shipped file (incl. previews and every `verify.json`); every entry's size/SHA-256 matches the
  file on disk; no entry points to a missing file; every entry has a non-empty source reference.

## Manual verification (human, by perception)
Work through T4.1's page in the review app (items from `assets/verify.json`):
1. Skim the manifest: the entries read like the bundle you just reviewed (sprites, tiles, world,
   audio, previews, docs all represented; nothing obviously missing or alien).
2. Spot-open 2–3 entries: the path exists and the source reference reads plausibly.
Report ACCEPT/REJECT with notes.

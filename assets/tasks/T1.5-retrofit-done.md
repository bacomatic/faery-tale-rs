## Implementation

### Part A — docs (no asset changes)
1. T0.1/T0.2: replace the "Manual verification" section with: *"No Reviewer step — internal tooling,
   nothing shipped. Correctness is exercised by the downstream assets."* Keep the pytest steps as
   an optional Implementer self-check.
2. T1.1: fix the source citations (`fmain2.c:367`, `fmain2.c:1569`); add `blackcolors.json` to Outputs
   and to the `palettes/` line of the plan's Output layout; add `previews/` to both.
3. T1.1/T1.2/T1.3: rewrite "Manual verification" in the perception style used by T1.4
   (work through the task's page in the review app: glance at counts and spot values, look at
   previews; no transcription or code).
   Mark the self-check headings "(optional aid)". Name T1.3's two output files.

### Part B — missing shipped artifacts
4. **Palette previews:** emit `assets/palettes/previews/<palette>.png`, one swatch strip per
   palette JSON, in index order with fixed-size cells. For `region_overrides.json`, emit
   `pagecolors` with each region's color-31 variant applied. Generate these from the **shipped JSON**
   (not by re-reading `src/`) so the previews show exactly what ships.
5. **`assets/palettes/verify.json`** (T1.1 items, `view: palette`): one item per palette file
   with its expected entry `count` (`pagecolors` 32, `textcolors` 20, `introcolors` 32,
   `sun_colors` 53, `blackcolors` 32), a few `rgb4`→`rgba8` spot values with source `citations`,
   and the matching preview PNG in `files` with a `look_for`. Descriptions must come from source or
   reference (e.g. "`blackcolors.png` — all black"; color character read off the `rgb4` values).
   Do not invent descriptions of in-game use.
6. **`assets/tables/verify.json`:** T1.2 items (`view: table`) — per table, the expected shape
   (from T1.2's spec list) as `counts` and 1–2 spot values with `file:line` citations (the JSON
   already carries `source`/`line`). T1.3 items — item count and a couple of named entries with
   citations.
7. **Fix the T1.2 `semantics` line ranges** (see the audit table). Edit the `SEMANTICS` strings in
   `tools/extract_tables.py` and re-run it. Don't hand-edit the JSON. Each cited range must cover the
   whole declaration, from its first line through the closing `};`. Re-read every range against
   `src/` after the fix. Only the `semantics` text should change in the regenerated JSON. Apply the same
   whole-block rule to every citation written in `verify.json` (steps 5–6).

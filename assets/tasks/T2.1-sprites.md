# T2.1 — Sprites extractor extension

> Read [`_SHARED.md`](_SHARED.md) first. Implementer produces the assets; a separate Reviewer accepts them by inspection (human-in-the-loop).

## Dependencies
T0.1, T1.1 (accepted palettes).

## Inputs (read-only)
- `tools/extract_sprites.py` (already decodes all 18 cfiles: 5 bitplanes, transparency = index 31, `pagecolors[]`)
- `assets/palettes/pagecolors.json` (accepted T1.1 output) — use this for RGBA rendering rather
  than re-reading the palette from `src/`, so the bundle stays self-consistent
- `CFILES` table (frame counts) in the source
- Existing `sprite_output/` (730 files) for regression diff
- Art-binding tables (former T1.2 group B): `statelist`, `diroffs`, `fallstates` (animation
  state → frame), `setfig_table` (NPC type → sheet + base frame), `inv_list` (item → icon +
  display name). Read them from source, or from temporary tables written by
  `tools/extract_tables.py` to `tools/results/tables/`. Meaning: `reference/logic/sprite-rendering.md`
  ("Lookup-table data") and `reference/RESEARCH-data-structures.md` §1.5, §2.4, §2.6.

## Implementation
Extend `tools/extract_sprites.py`:
1. Per-actor JSON atlas: frame→rect, dimensions, transparency index 31, frame counts from `CFILES`.
   Name frames by meaning instead of shipping the raw index tables: animations per direction
   (walk, fight, death, sinking, …) with their frame lists and weapon-overlay offsets
   (from `statelist`/`diroffs`/`fallstates`), which sheet and frames each NPC type uses
   (`setfig_table`), and which icon and display name each inventory item uses (`inv_list`).
   Cite the source line for each binding.
2. Add an **indexed-PNG** output mode (current output is RGBA).
3. Emit into `assets/sprites/<actor>/`: `frame_000.png …`, `<actor>_sheet.png`, `<actor>.json`.
4. Emit a **1-bit highlight mask** per sheet: `<actor>_highlightmask.png` (index ∈ 16–24; transparency follows 31).
5. Keep labeled/2x debug variants OUT of the shipped bundle.
6. Add T2.1 items to `assets/sprites/verify.json`: per actor, point at the sheet (and a
   representative frame) with a short **source-derived `look_for`** (actor, facing, dominant
   `pagecolors[]` colors, cfile index) and a frame `count` from `CFILES`, so a reviewer can view it
   in the review app and confirm.

## Implementer self-check (optional aid)
- RGBA frames diff-clean vs `sprite_output/`; indexed PNG round-trips; mask matches 16–24;
  `<actor>.json` frame counts == `CFILES` and every rect in-bounds.

## Manual verification (human, by perception)
Work through T2.1's page in the review app (items from `assets/sprites/verify.json`); **look at the PNGs** and confirm each matches its description:
1. Open several sheets (heroes + a few NPCs/enemies): each shows the described actor with correct
   facings and colors — recognizable from the game, not garbage, clean transparency.
2. Glance at a highlight mask next to its sheet: the set bits sit on the plausible areas
   (vegetation-boost colors), roughly tracking the sprite silhouette.
3. Skim one `<actor>.json`: frame count and rects look sane for that actor; a named animation
   (e.g. walk south) points at frames that show that pose.
Report ACCEPT/REJECT with the actors checked.

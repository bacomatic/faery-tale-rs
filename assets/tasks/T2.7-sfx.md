# T2.7 — SFX extractor

> Read [`_SHARED.md`](_SHARED.md) first. Implementer produces the assets; a separate Reviewer accepts them by inspection (human-in-the-loop).

## Dependencies
T0.1.

## Inputs (read-only)
- ADF `src/assets/image` blocks 920–930 (11 blocks = 5,632 B buffer, `SAMPLE_SZ` `fmain.c:645`,
  loaded by `load_track_range(920,11,sample_mem,8)` `fmain.c:1028`)
- Sample framing: `read_sample()` `fmain.c:1033-1041` — each of the 6 samples is a **4-byte
  big-endian length prefix** followed by that many bytes of 8-bit PCM.
- Playback: `effect(num,speed)` → `playsample(sample[num], sample_size[num]/2, speed)`
  `fmain.c:3617-3619`; `speed` is a **Paula period, randomized per trigger** at the call sites
  (`fmain2.c:238-241`; `fmain.c:1488`, `1680`, `1690`, `2262`). **There is no fixed native rate.**

## Implementation
Create `tools/extract_sfx.py`:
1. Extract the 6 samples by **walking the 4-byte BE length prefixes** (do not split by fixed
   size; do not include the prefixes in the PCM).
2. Write WAV, byte-exact PCM (no resample, no normalize). WAV header rate = the effect's
   **base-period rate**: NTSC Paula clock 3,579,545 ÷ the base period at its trigger call site
   (e.g. effect 2 → 3579545/500 ≈ 7159 Hz). If an effect has multiple call sites with different
   bases (effect 5: 3200 and 1800), pick one and document the choice. The rate is **nominal
   container metadata** — the authoritative playback data is `sfx.json`.
3. Emit `assets/audio/sfx/sfx.json`: per effect — buffer offset, byte length, and **every**
   trigger's period expression (`base`, random range, RNG fn) with call-site citations.
4. Add T2.7 items to `assets/audio/sfx/verify.json`: one item per WAV with a one-line “what you
   should hear” `look_for` cue plus its buffer offset, so a reviewer can play it in the review app
   and confirm.

## Outputs
- `assets/audio/sfx/sfx_<n>.wav` ×6 + `assets/audio/sfx/sfx.json`
- `assets/audio/sfx/verify.json` (T2.7 items: file ↔ “what you should hear” cue + offset)
- `tools/tests/test_extract_sfx.py` (optional aid, not a deliverable)

## Implementer self-check (optional aid)
- WAV PCM bytes match the prefixed-framed samples exactly (no prefix bytes, no resample/normalize);
  8-bit PCM; header rate == 3,579,545 ÷ documented base period; `sfx.json` periods match the
  cited call sites.

## Manual verification (human, by perception)
Work through T2.7's page in the review app (items from `assets/audio/sfx/verify.json`); **play the WAVs**:
1. Confirm exactly 6 WAV files; play each — it's the sound you know from the game and matches
   its cue (sword hit, door, spell, …), at a sensible pitch/speed.
2. Glance at `sfx.json`: 6 entries, each with a period expression and citation.
Report ACCEPT/REJECT with the SFX played.

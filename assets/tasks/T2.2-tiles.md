# T2.2 — Background tile atlas extractor

> Read [`_SHARED.md`](_SHARED.md) first. Implementer produces the assets; a separate Reviewer accepts them by inspection (human-in-the-loop).

## Dependencies
T0.1, T1.1 (accepted palettes), T2.3 (mask store) and T2.5 (terra entries) for the shadow-mask atlas.

## Inputs (read-only)
- ADF `src/assets/image` (image_mem groups)
- `file_index` (`src/fmain.c:615-626`) — region → image-group block numbers. Read from source or
  from the temporary table written by `tools/extract_tables.py` to `tools/results/tables/`. Used
  only to organize the output per region; not shipped.
- `assets/palettes/pagecolors.json` + `assets/palettes/region_overrides.json` (accepted T1.1
  output) — for RGBA rendering and the region-4/9 color-31 overrides
- `experiment/shaders/` (earlier decode; it only read the top 16 of each tile's 32 rows)

## Implementation
Create `tools/extract_tiles.py`. Per region:
1. 256 tiles, **16×32** (`fsubs.asm:755-771`, `fsubs.asm:1701`, `fmain.c:1981`), **5 bitplanes**,
   group-major then plane-major.
2. Offset formula: `offset(T,P,R) = (T/64)*20480 + P*4096 + (T%64)*64 + R*2`, R in 0..31.
3. Emit indexed PNG + RGBA PNG + 1-bit highlight mask (index ∈ 16–24) + 1-bit **shadow mask**
   atlas (per tile cell: the `assets/masks/` entry named by the tile's terra byte 0, or empty when
   the occlusion mode in terra byte 1 is 0, `fmain.c:2577-2595`; `tiles[].mask` / `mask_mode`) +
   `tiles.json`, whose
   `index_31` lists the tiles containing colour 31 (the only colour `fade_page` swaps per region,
   `fmain2.c:381-386`). In region 9 colour 31 is `0x00f0` while `secret_timer` runs (Crystal Orb,
   `fmain.c:3307`; `fmain2.c:383`) — how hidden passages are revealed, a critical gameplay feature.
   `tiles.json.index_31.secret_timer` records the colour; the master atlas (T2.2.1) ships the two
   affected tiles as variants.
4. Add T2.2 items to `assets/tiles/verify.json`: per region, point at the atlas files with a short
   **source-derived `look_for`** (region name from `file_index[]`, expected terrain/colors), so a
   reviewer can view the atlas in the review app and confirm.

## Outputs
- `assets/tiles/region_<NN>/{atlas_indexed.png, atlas_rgba.png, atlas_highlightmask.png, atlas_shadowmask.png, tiles.json}`
- `assets/tiles/verify.json` (T2.2 items: per-region file ↔ source-derived description)
- `tools/tests/test_extract_tiles.py` (optional aid, not a deliverable)

## Implementer self-check (optional aid)
- Indexed decode matches a hand-decoded bitplane reference (e.g. hand-compute the byte offset for
  tile 65, plane 2, row 3); RGBA == palette-applied indices (correct color-31 override for
  regions 4/9); mask bits set exactly where index ∈ 16–24.

## Manual verification (human, by perception)
Work through T2.2's page in the review app (items from `assets/tiles/verify.json`); **look at the atlases** and confirm each matches its description:
1. Open each region's RGBA atlas: the terrain is recognizable as that region from the game
   (village, forest, desert, dungeon, …) with correct colors — not garbage, not shifted/striped.
2. Compare one indexed atlas against its RGBA twin at a glance: same imagery.
3. Glance at one highlight mask next to its atlas: set bits sit on vegetation-type tiles.
Report ACCEPT/REJECT with the regions checked.

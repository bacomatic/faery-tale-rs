# T3.1 — Reference shaders & light-level reference renders

> Read [`_SHARED.md`](_SHARED.md) first. Implementer produces the assets; a separate Reviewer accepts them by inspection (human-in-the-loop).
> The GLSL is **reference material only** — it is verified by the port, not by this pipeline.
> The perception-reviewable deliverable here is the **reference renders**.

## Dependencies
T2.1 (sprite highlight mask), T2.2 (tile highlight mask) — mask format must be final.

## Inputs (read-only)
- `experiment/shaders/` — verified day/night decomposition (`daynight_live.glsl`,
  `daynight_bank.glsl`, `daynight_lut.json`, `compare.py`, `FINDINGS.md`)
- `src/fmain2.c` `fade_page()` (effect source of truth)

## Implementation
Hand-author GLSL (with pseudocode comments — not generated) under `assets/shaders/`:
- `fade_to_black.glsl` — uniform multiply (also fade-from-black / transitions).
- `daynight_live.glsl` / `daynight_bank.glsl` — full day/night incl. vegetation night boost;
  port the verified reference from `experiment/shaders/`.
- `README.md` — inputs/uniforms per shader; indexed-path vs RGBA+`highlight_mask` matrix.
  State explicitly: **the GLSL is reference-only and is validated by the porting effort.**

Also produce **light-level reference renders** under `assets/shaders/previews/` — visual cues
showing how things should appear, generated with the verified Python `fade_page()` port from
`experiment/shaders/` (bit-exact ground truth, NOT the GLSL):
- Subjects: **every region's tile atlas** (T2.2) and **every actor sheet that appears outdoors**
  (T2.1; indoor-only actors are never faded — review decision), each rendered at a spread of light levels
  (e.g. full day → dusk steps → night) plus the `moonlight_blue` and `green_jewel` effects.
- Name files self-descriptively (e.g. `region_02_light128.png`, `julian_moonlight.png`) and
  index them in a `previews/README.md`. Non-authoritative; ship with the bundle — they double
  as golden images the port can diff against.

Add T3.1 items to `assets/shaders/verify.json`: the preview progressions (grouped per subject,
each with a `look_for` of the expected day/dusk/night/moonlight/green-jewel appearance, derived
from `fade_page()`), and `README.md` (`view: markdown`).

## Outputs
- `assets/shaders/*.glsl` + `assets/shaders/README.md` (reference-only)
- `assets/shaders/previews/*.png` + `assets/shaders/previews/README.md` (reference renders)
- `assets/shaders/verify.json` (T3.1 items)

## Implementer self-check (optional aid)
- Renders produced via the Python reference (`experiment/shaders/fade_page.py` LUT path), not
  ad-hoc math; `moonlight_blue`, `green_jewel`, and channel floors match `fade_page()` arithmetic
  in `fmain2.c`; mask semantics match the emitted masks (index ∈ 16–24).

## Manual verification (human, by perception)
Work through T3.1's page in the review app (items from `assets/shaders/verify.json`):
1. Flip through the preview renders: day/dusk/night progressions look like the game —
   vegetation pops at night, moonlight is blue, green jewel tints correctly, across regions
   and actors.
2. Read `shaders/README.md`: effect list complete, indexed-vs-RGBA+mask story coherent, and the
   reference-only status of the GLSL is stated.
Report ACCEPT/REJECT with notes. (The GLSL itself is **not** gated here — the port validates it.)

# T1.4 — Narrative text extractor

> Read [`_SHARED.md`](_SHARED.md) first. Implementer produces the assets; a separate Reviewer accepts them by inspection (human-in-the-loop).

## Dependencies
T0.1.

## Inputs (read-only)
- `src/narr.asm` — 519 lines of `dc.b` directives
- `reference/_discovery/narr-asm-complete-message-database.md` (cross-check only).

Relevant labels in `narr.asm` (each block is a run of null-terminated strings):
- `_event_msg` — 39 event messages
- `_place_msg` — 27 place-arrival messages
- `_inside_msg` — 23 interior-arrival messages
- `_speeches` — 61 NPC dialogue entries

Additional structures (needed for a self-sufficient bundle):
- `q1`–`q8` under `_question` — 8 riddle prompts (plain null-terminated strings, offset table `qq`)
- `_placard_text` — 20 positioned scroll-text entries (`mst` offset table, `msg1`–`msg12` incl.
  a/b variants); each entry is a sequence of `XY`-positioned segments (`XY`=128, then `x/2`,
  then `y`, then text) terminated by `ETX`=0 (`narr.asm:230-231`)
- `_place_tbl` — 29 rows × 3 bytes (`lo`, `hi`, `place_msg` index): place-code range → message
- `_inside_tbl` — 37 rows × 3 bytes (`lo`, `hi`, `inside_msg` index)

## Implementation
1. Create `tools/extract_text.py`. Honor `--src-dir` (default `src/`); parse `src/narr.asm`.
2. Parse the `dc.b` directives directly from the assembly:
   - **Strip `;` comments** (inline and full-line) — but only a `;` **outside quoted literals**
     starts a comment. Known trap: `narr.asm:197` is an entire commented-out message
     (`;  dc.b "He entered the garden area.",0`) — it must NOT become an entry.
   - Reassemble each message from consecutive `dc.b` fragments **until the `,0` terminator**
     (one logical string may span several `dc.b` lines).
   - **Empty-string entries:** a standalone `dc.b 0` with no preceding unterminated string is a
     complete **empty entry** (`""`), not a terminator of the previous message. `_place_msg[0..1]`
     (`narr.asm:165-166`, "; no message / ; do not change") and `_inside_msg[0..1]`
     (`narr.asm:200-201`) are exactly this; they must be emitted to preserve index alignment.
   - Handle both `'single'` and `"double"` quoted string literals, including the embedded-quote
     idiom `...',"'",'...` and bare numeric byte operands (e.g. `13` = CR, `0` = terminator).
   - Collect the strings under `_event_msg`, `_place_msg`, `_inside_msg`, and `_speeches`, stopping
     each block at the next label/`cseg`/`dseg` directive.
3. Split into `event_msg.json`, `speeches.json`, `place_msg.json`, `inside_msg.json`, indexed in
   source order (so entry N matches the numbered comments in `narr.asm`).
4. Preserve `%` (player/character name) and `$` (target) placeholders verbatim; keep embedded `\r`
   (byte `13`) as-is.
5. **Riddles:** extract `q1`–`q8` → `question.json` (8 strings, indexed 0–7 per the `qq` table order).
6. **Placard text:** extract the 20 `_placard_text` entries → `placard_text.json`. Each entry is a
   list of segments `{x_half, y, text}` in source order (decode `XY`=128 marker, then the stored
   `x/2` byte, then `y`, then the text run; entry ends at `ETX`=0). Document that pixel
   `x = x_half × 2`. Preserve segment order and text verbatim.
7. **Lookup tables:** extract `_place_tbl` (29 rows) → `place_tbl.json` and `_inside_tbl`
   (37 rows) → `inside_tbl.json`, each row `{lo, hi, msg_index}` in source order (first match
   wins — preserve order). Carry the source-comment location names as a `comment` field.

# T2.4 — IFF/ILBM screens extractor

> Read [`_SHARED.md`](_SHARED.md) first. Implementer produces the assets; a separate Reviewer accepts them by inspection (human-in-the-loop).

## Dependencies
T0.1.

## Inputs (read-only)
- `src/assets/` — exactly **9** ILBM files (verified `FORM…ILBM`):
  `p1a` `p1b` `p2a` `p2b` `p3a` `p3b` `page0` `winpic` `hiscreen`
  (intro/placard/win/hi-score). Other files in `src/assets/` (`fmain`, `C.faery`, `E.faery`,
  `image`, `songs`, `v6`, fonts) are **not** screens — do not decode them here.

## Implementation
Create `tools/extract_screens.py`:
1. Parse IFF/ILBM chunks: `BMHD`, `CMAP`, `BODY` with **ByteRun1** decompression.
2. Convert to RGBA PNG. Take dimensions/depth from each file's `BMHD` — they vary
   (`page0`/`winpic` 320×200; `hiscreen` 640×57 hires-width; placards smaller). Do not assume 320-wide.
3. Add T2.4 items to `assets/screens/verify.json`: one item per screen with a short
   **source/reference-derived `look_for`** of what the image should depict (e.g. `p1a.png` —
   “opening placard, castle at dusk”), so a reviewer can view it in the review app and confirm.

## Outputs
- `assets/screens/<name>.png`
- `assets/screens/verify.json` (T2.4 items: file ↔ source/reference-derived description)
- `tools/tests/test_extract_screens.py` (optional aid, not a deliverable)

## Implementer self-check (optional aid)
- Each screen decodes; RGBA matches a hand-decoded reference; PNG dimensions == BMHD.

## Manual verification (human, by perception)
Work through T2.4's page in the review app (items from `assets/screens/verify.json`); **look at the PNGs**:
1. Confirm exactly 9 PNGs; open each — it's the screen you know from the game (intro placards,
   win picture, hi-score screen), correct colors, nothing garbled.
Report ACCEPT/REJECT with the screens checked.

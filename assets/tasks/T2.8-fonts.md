# T2.8 — Fonts extractor

> Read [`_SHARED.md`](_SHARED.md) first. Implementer produces the assets; a separate Reviewer accepts them by inspection (human-in-the-loop).

## Dependencies
T0.1.

## Inputs (read-only)
- `src/assets/fonts/` (DiskFont data, ID `0x0F80`) — **exactly two size files, both used by
  the game**: `Amber/9` (loaded via `LoadSeg("fonts/Amber/9")`, `fmain.c:774`) and `Topaz/8`
  (the game opens **ROM** topaz-8 via `OpenFont(&topaz_ta)`, `fmain.c:650,778`; the disk copy
  stands in for the ROM font a port won't have). The `.font` header files are **not** used by
  the game — skip them and any sizes they declare.

## Implementation
Create `tools/extract_fonts.py`:
1. Parse the DiskFont size files (`Amber/9`, `Topaz/8`; hunk ID `0x0F80`): glyph bitmaps.
2. Emit per-glyph PNG + a packed glyph atlas.
3. Emit metrics JSON: `y_size`, `baseline`, `modulo`, `lo_char`/`hi_char`, `char_loc` (offset+width).
4. Add T2.8 items to `assets/fonts/verify.json`: both packed atlases, plus a few glyphs (e.g. `A`,
   `0`, first/last in `lo_char`..`hi_char`) with the expected character as `look_for`, so a reviewer
   can view them in the review app and confirm.

## Outputs
- One directory per font **size file** (2 total: `amber_9`, `topaz_8`):
  `assets/fonts/<font>_<size>/glyphs/*.png`, `assets/fonts/<font>_<size>/<font>_<size>.json`
- `assets/fonts/verify.json` (T2.8 items: glyph file ↔ expected character)
- `tools/tests/test_extract_fonts.py` (optional aid, not a deliverable)

## Implementer self-check (optional aid)
- Glyph bitmaps match hand-decoded DiskFont data; metrics match the header; `char_loc`
  offsets+widths index the packed atlas without overlap/overflow.

## Manual verification (human, by perception)
Work through T2.8's page in the review app (items from `assets/fonts/verify.json`); **look at the glyph PNGs / atlases**:
1. Open both packed atlases (`amber_9`, `topaz_8`): the full character set reads correctly —
   amber is the game's in-game text face, topaz the familiar Amiga system font; no clipped or
   scrambled glyphs.
2. Look at the listed individual glyphs (e.g. `A`, `0`, first/last): each shows the
   expected character.
Report ACCEPT/REJECT with the glyphs checked.

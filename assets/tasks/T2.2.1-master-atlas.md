# T2.2.1 — Master tile atlas (deduplicated, used tiles only)

> Read [`_SHARED.md`](_SHARED.md) first. Implementer produces the assets; a separate Reviewer accepts them by inspection (human-in-the-loop).

Added during the T2.2 review (user request, 2026-09-28): porting efforts can use either the
per-region atlases (T2.2) or one master atlas of every tile the game can actually draw, with a
reference map so the original map data still works with the master atlas.

## Dependencies
T2.2 (per-region atlases), T2.5 (region maps + sector pools).

## Inputs (read-only)
- `assets/tiles/region_<NN>/atlas_indexed.png` (T2.2) — the 256 tiles per region, palette indices.
- `assets/world/region_<N>.json` `region_map.grid` + `assets/world/sectors_{outdoor,indoor}.json`
  (T2.5) — the map data the game draws from.
- `assets/palettes/pagecolors.json`, `assets/palettes/region_overrides.json` (T1.1).

## What "used" means
The tile drawn at any map position is `sector_mem[map_mem[sec_num] * 128 + row * 16 + col]`
(`src/fsubs.asm:565-604`), where `map_mem` is the region's 32×64 map (block `file_index[].region`)
and `sector_mem` the sector pool (block `file_index[].sector`), `src/fmain.c:3557-3562`. A tile
index is **used by a region** when some sector referenced by that region's map contains it.
- Regions 1/3 and 5/7 load identical image blocks (`src/fmain.c:617,619,621,623`) so their tiles
  dedupe against each other.
- Regions 8 and 9 share one map and one sector pool (blocks 192/96, `src/fmain.c:624-625`) but
  different art. The indoor map is a set of islands (4-connected non-zero sectors; sector 0 is
  tile 0, impassable in both terra sets), and the region loaded on an island is decided on entry:
  `doorlist[].secs == 1` → region 8, else 9 (`src/fmain.c:1919-1927`); doors whose outside
  coordinate is itself indoor (the stargate pair) land with the region derived from the
  coordinates (`src/fmain.c:1936-1950`, `2632-2637`), i.e. region 8 for map columns 0–63; the
  necromancer sequence loads region 9 (`src/fmain.c:1784-1788`). A sector counts for a region only
  if its island is entered with that region loaded. Result: 3 islands are shown as region 9
  (castle/village/maze caves, spider/necromancer, dragon cave), 48 as region 8, 16 have no entry
  at all. The crystal palace (sectors 121–124, `astral` group tiles) is region 8 only.

## Implementation
`tools/extract_master_atlas.py`:
1. For each region, collect the used tile indices from the map grid and sector pool.
2. Deduplicate used tiles by pixel content — verbatim source indices 0–31, no repainting. The key
   also holds the region's colour-31 value (when the tile uses index 31, `fmain2.c:381-386`) and
   the tile's shadow-mask entry + occlusion mode (`fmain.c:2577-2595`), so `atlas_rgba.png` and
   `atlas_shadowmask.png` are exact 1:1 lookups next to `atlas_indexed.png` /
   `atlas_highlightmask.png`. Art that appears with different masks/modes is kept once per
   combination (11 cases → 10 extra tiles).
3. Append a **secret-timer variant** of every master tile drawn with colour 31 under region 9
   (`0x00f0` while `secret_timer` runs, `fmain2.c:383`): identical indices, green in the RGBA
   atlas. A port using RGBA draws the variant while the timer runs; one using the indexed atlas
   swaps palette entry 31. `master.json.index_31.secret_variants` links original ↔ variant. The
   review app's image viewer offers a colour-31 selector for indexed PNGs (the four
   `palettes/region_overrides.json` values), so the indexed atlas can be checked under each.
4. Emit the master atlas (indexed, RGBA, highlight mask, shadow mask) and `master.json` with, per
   master tile, its rectangle, `color_31`, `mask`/`mask_mode` and every `(region, tile)` that maps
   to it; plus `region_maps`: for
   each region a 256-entry list `tile index → master index` (`null` = never drawn), which is the
   reference map that lets the original `map`/`sector` data address the master atlas.
5. Add T2.2.1 items to `assets/tiles/verify.json`.

## Outputs
- `assets/tiles/master/{atlas_indexed.png, atlas_rgba.png, atlas_highlightmask.png, atlas_shadowmask.png, master.json}`
- `assets/tiles/verify.json` (T2.2.1 items)
- `tools/tests/test_extract_master_atlas.py` (optional aid)

## Implementer self-check (optional aid)
- Every master tile's pixels equal the source region tile's pixels; every used `(region, tile)`
  resolves through `region_maps` to a tile with identical pixels; unused entries are `null`.

## Manual verification (human, by perception)
Work through T2.2.1's page in the review app:
1. Open the master RGBA atlas: it reads as a catalogue of world tiles (every terrain family
   represented once), no duplicates visible, no garbage.
2. Glance at `master.json`: the counts (unique tiles, per-region used/unused) are plausible and
   the reference map for one region is a 256-entry list.
Report ACCEPT/REJECT.
